# Vira Shuttle - cPanel / Apache Deployment

سامانهٔ رزرو سرویس دانشگاه با React / TypeScript / Vite، Express و MySQL.
گزارش اصلاحات و محدودهٔ بررسی: [بررسی ۱۹ اکتبر ۲۰۲۶](docs/REVIEW-2026-10-19.md).
اصلاح تکمیلی: [زوم موبایل، انتخاب ایستگاه و اسکن تمام‌صفحهٔ پیوسته — ۲۰ اکتبر ۲۰۲۶](docs/REVIEW-2026-10-20.md).

Frontend: `https://vira.bog.co.ir`
Backend: `https://vira.bog.co.ir/api1`

Important:
- Browser code must only call relative `/api1/...` paths.
- Apache/LiteSpeed must not rewrite or proxy `/api1/*` away from this host.
- SPA fallback must never capture `/api1` or `/socket`.

## Files
- `public/.htaccess`
- `backend/.htaccess`
- `backend/config/backend-config/index.js`
- `.env`
- `.env.example`
- `public/runtime-config.json`

## Apache/LiteSpeed flow
1. Request hits `https://vira.bog.co.ir/api1/...`
2. API app on the same host returns JSON
3. Frontend routes fall back to `index.html` only for non-API paths

## Notes
- Frontend `VITE_API_BASE_URL` should stay `/api1`.
- Backend CORS must allow `https://vira.bog.co.ir`.
- No browser-visible direct backend origin calls.

## توسعهٔ محلی

Node.js `20.19+` و MySQL لازم است. وابستگی‌های فرانت و بک‌اند جدا نصب می‌شوند:

```sh
npm ci
npm --prefix backend ci
cp .env.example .env
```

فایل `.env` را با مشخصات پایگاه دادهٔ محلی و رمزهای تصادفی واقعی تکمیل کنید.
برای توسعه `BACKEND_NODE_ENV=development` و `CORS_INCLUDE_LOCALHOST=true` قرار دهید.
`JWT_SECRET` و `SESSION_SECRET` هرکدام حداقل ۳۲ کاراکتر و رمز مدیر حداقل ۱۲ کاراکتر است.
برای ساخت مقدار تصادفی می‌توان از `openssl rand -hex 32` استفاده کرد.
پایگاه داده باید از قبل ایجاد شده باشد؛ سرور جدول‌ها و تغییرات افزایشی لازم را در شروع اعمال می‌کند.
`SEED_DEMO_DATA=false` پیش‌فرض امن است؛ داده‌های نمونه فقط با فعال‌سازی صریح آن در محیط غیرتولیدی وارد می‌شوند.

در دو ترمینال:

```sh
npm --prefix backend start
```

```sh
npm run dev
```

فرانت روی `http://127.0.0.1:3000` اجرا می‌شود و Vite درخواست‌های `/api1` و `/api` را به
`http://127.0.0.1:5005` می‌فرستد. برای بک‌اند محلی متفاوت، `VITE_DEV_API_TARGET` را تنظیم کنید.
مقادیر `VITE_` عمومی‌اند و نباید شامل کلید یا رمز باشند.

## صدور و اسکن بلیط

QR نمایشی حاوی شناسهٔ کامل خرید است. رانندهٔ همان سرویس یا رانندهٔ مجاز برای ایستگاه مسیر
می‌تواند آن را اسکن کند؛ تخصیص جداگانهٔ ایستگاه برای رانندهٔ خود سرویس ضروری نیست.
مرورگرهای بدون `BarcodeDetector` از رمزگشای محلی `jsQR` استفاده می‌کنند.
دوربین به HTTPS یا localhost و اجازهٔ کاربر نیاز دارد. ورود کد چهاررقمی با ارقام فارسی/عربی نیز پشتیبانی می‌شود.
در خرید چند صندلی، QR مشترک همهٔ مسافران همان خرید را یک‌بار تأیید می‌کند.
اعتبار روزانه با منطقهٔ زمانی `Asia/Tehran` تعیین می‌شود؛ بلیط لغوشده، روز گذشته یا اسکن‌شده دوباره پذیرفته نمی‌شود.
در صورت تداخل کد دستی بلیط‌های قدیمی، کاربر باید QR کامل را نشان دهد.
در حالت دوربین، نتیجهٔ هر اسکن در بالای تصویر نمایش داده و خودکار محو می‌شود؛ دوربین برای بلیط بعدی روشن می‌ماند.
تصویر دوربین تمام صفحه را می‌پوشاند و کادر اجباری برای قرارگیری QR ندارد؛ وضعیت اسکن و دکمهٔ ورود دستی روی تصویر قرار دارند.
کدی که همچنان جلوی دوربین است دوباره ارسال نمی‌شود. کد متفاوت بلافاصله قابل بررسی است؛ برای تلاش مجدد همان کد، آن را کوتاه از تصویر دوربین خارج و دوباره نشان دهید.
آمار داشبورد هنگام خروج از اسکنر تازه می‌شود تا دریافت گزارش‌ها، بررسی بلیط بعدی را معطل نکند.

درخواست خرید جدید `Idempotency-Key` ارسال می‌کند تا تکرار همان درخواست دوباره پول کم نکند.
کلاینت‌های قدیمیِ بدون این هدر همچنان پشتیبانی می‌شوند. بازخورد سفر پس از ثبت سوارشدن فعال می‌شود.

## انتخاب ایستگاه و درخواست مسیر

بازکردن فهرست ایستگاه در رزرو مسافر و درخواست مسیر راننده، کیبورد را خودکار فعال نمی‌کند.
انتخاب مستقیم از فهرست امکان‌پذیر است؛ جست‌وجو با لمس فیلد آن یا پیمایش عمدی با کیبورد فعال می‌شود.
پیمایش Tab، بستن با Escape و بازگشت فوکوس به دکمهٔ انتخاب حفظ شده‌اند.
ورودی ساعت حرکت راننده با انتخابگر ساعت مرورگر، عرض محدود و ارتفاع ۴۸ پیکسل نمایش داده می‌شود.

## اعتبارسنجی

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

آزمون‌های API و مرورگر به **MySQL محلیِ مخصوص آزمایش** با اجازهٔ ایجاد/حذف پایگاه داده نیاز دارند.
`VIRA_TEST_DB_URL` باید loopback باشد؛ هر اجرا یک پایگاه دادهٔ تصادفی `vira_test_*` می‌سازد و همان را پاک می‌کند.
این مقدار را به پایگاه دادهٔ عملیاتی یا اطلاعات ورود آن متصل نکنید.

```sh
VIRA_TEST_DB_URL=mysql://root@127.0.0.1:33317 npm run test:integration
VIRA_TEST_DB_URL=mysql://root@127.0.0.1:33317 VIRA_TEST_POOL_SIZE=1 npm run test:integration
npx playwright install chromium
VIRA_TEST_DB_URL=mysql://root@127.0.0.1:33317 npm run test:browser
```

برای مرورگر نصب‌شدهٔ سازگار، مسیر آن را با `PLAYWRIGHT_CHROMIUM_EXECUTABLE` بدهید.
برای اجرای همین سناریوها روی خروجی تولید، ابتدا `npm run build` و سپس آزمون مرورگر را با `VIRA_BROWSER_PREVIEW=true` اجرا کنید.
آزمون مرورگر پورت‌های `3017` و `5017` را موقتاً استفاده می‌کند.
گزارش تصویری/trace در `test-results/` تولید می‌شود و در Git ثبت نمی‌شود.
جزئیات نتایج، هشدارهای باقی‌ماندهٔ ابزار ساخت و محدودیت آزمون دوربین در گزارش بررسی آمده است.

## انتشار سازگار با سرویس فعلی

- نقطهٔ ورود Passenger همان `backend/server.js` است؛ aliasهای `/api` و `/api1` حفظ شده‌اند.
- خروجی `npm run build` در `dist/` است. فایل‌های آن به ریشهٔ فرانت می‌روند؛ `.htaccess` و `runtime-config.json` نیز باید منتشر شوند.
- پوشهٔ بک‌اند همراه `package-lock.json`، `db_schema.sql`، `demo_seed.sql` و ماژول‌های جدید منتشر شود؛ سپس وابستگی‌های تولید با `npm ci --omit=dev` در همان پوشه نصب شوند.
- تنظیمات Passenger موجود در `backend/.htaccess` وابسته به هاست است؛ مسیر حساب و BaseURI تنظیم‌شدهٔ میزبان را حفظ کنید. وب‌سرور باید `/api1` را واقعاً به برنامه برساند و آن را به SPA نفرستد.
- پیش از تغییر تولید، از پایگاه داده و فایل‌های ذخیره‌شده پشتیبان بگیرید و نسخه را ابتدا روی کپی staging اجرا کنید. راه‌اندازی مجدد سرور به داده‌های موجود نیاز دارد؛ خطای اتصال یا مهاجرت، شروع سرویس را متوقف می‌کند.
- فایل واقعی `.env` و داده‌های `backend/storage/` را با انتشار کد جایگزین یا پاک نکنید. فایل‌های عملیاتی از Git خارج‌اند. برای ذخیره‌سازی بیرون از web root، `TICKET_STORAGE_ROOT` را روی مسیر خصوصی و قابل‌نوشتن قرار دهید؛ مسیر فعلی ذخیره‌سازی قدیمی را بدون انتقال فایل‌های موجود عوض نکنید.
- فایل `backend/storage/.htaccess` دسترسی مستقیم Apache به ذخیره‌سازی را می‌بندد؛ دریافت پیوست از API احراز هویت‌شده انجام می‌شود. در وب‌سرور دیگر، قاعدهٔ منع دسترسی معادل لازم است.
- تغییرات پایگاه داده افزایشی‌اند: جدول درخواست خرید و بازخورد، و شناسهٔ رانندهٔ ثبت‌شده هنگام فروش اضافه شده‌اند. شاخص یکتای تک‌ستونی QR قدیمی به شاخص عادی تبدیل می‌شود تا خرید چند صندلی کار کند. اطلاعات بلیط و مالی حذف نمی‌شود. برای بازگشت کد، جدول‌ها و ستون‌های افزوده را نگه دارید.
- تنظیمات درگاه، callback، HTTPS، دسترسی دوربین و حساب‌های واقعی باید روی staging میزبان بررسی شوند. Push کد به GitHub به معنای deploy سایت نیست.
