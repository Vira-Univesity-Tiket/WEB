## دامنه و مرجع

این تغییر ادامهٔ بازطراحی دانشجو در commit `b1dcb3a3ee637060b686cfc492410cbfa43c7d30` است و روی شاخهٔ `feat/vira-driver-ui-redesign` انجام شده است. بک‌اند، پایگاه داده، migration، قرارداد API، شیوهٔ نگهداری توکن، حسابداری و قواعد اعتبار بلیت تغییر نکرده‌اند. نسخهٔ دانشجو و مدیریت بازطراحی مجدد نشده‌اند.

هر ۱۱ JPEG ارسالی باز و بررسی شد. ZIP نام‌برده‌شده در درخواست در فایل‌های تحویلی موجود نبود. شماره‌های جدول، نگاشت محتوایی فایل‌های ارسالی‌اند. پیش‌نویس انگلیسی مرحلهٔ حساب کنار گذاشته شد. JPEG وضعیت بررسی، دکمهٔ خاکستری و ناوبری دارد؛ طبق تصریح نسخهٔ نهایی در متن مأموریت، دکمه آبی و ناوبری حذف شده است.

## فایل‌ها و اتصال‌ها

- `views/DriverAppView.tsx`: ترکیب صفحه‌ها و چهار تب فعلی؛ ترتیب راست‌به‌چپ داشبورد، اسکن، درخواست مسیر و پروفایل.
- `components/driver/`: ورود/قوانین/بررسی، ثبت‌نام سه‌مرحله‌ای، داشبورد و درخواست مسیر؛ اجزای مشترک برند، ناوبری، وضعیت و اسکنر.
- `hooks/useDriverLogic.ts`: هماهنگی UI با API موجود، بازیابی نشست، منابع مستقل، مهار ارسال تکراری و کنارگذاشتن پاسخ‌های قدیمی. پس از ثبت مسافر، پاسخ خواندن پیش از ثبت نمی‌تواند آمار تازه را بازنویسی کند.
- `utils/driverRegistration.ts`: اعتبارسنجی سازگار با قرارداد موجود، تاریخ شمسی، صفر ابتدایی شناسه‌ها، مدارک مجاز و ساخت payload اصلی بدون متادیتای رابط.
- `driver.css` و import آن در `index.tsx`: سبک محدود به `.vira-driver` با رنگ‌های ویرا، فاصله‌ها، سطوح سفید، فرم‌های فارسی، safe area و ارتفاع انعطاف‌پذیر.
- `public/illustrations/driver/`: شش تصویر مستقل بریده‌شده از بخش تزئینی مراجع؛ هیچ تصویر کامل صفحه، متن فرم، دکمه یا QR مرجع در محصول استفاده نشده است. لوگوی اصلی و فونت محلی Vazirmatn موجود حفظ شده‌اند.
- `components/student/StationPicker.tsx`: فقط سه prop اختیاری label، placeholder و disabled برای استفادهٔ مشترک؛ پیش‌فرض و رفتار بخش دانشجو محفوظ است.
- `components/TicketCameraScanner.tsx`: فقط یکدست‌سازی واژهٔ نمایشی «بلیت»؛ decoder، stream و gate موجود حفظ شده‌اند.
- `tests/driver-ui.test.ts` و `tests/browser/driver*.{ts,spec.ts}`: آزمون‌های مرز ورودی، اسناد خصوصی، اتصال واقعی، پاسخ دیررس، نتیجهٔ نامشخص و مرور ده حالت در پنج عرض. selectorهای آزمون قبلی با labelهای جدید هماهنگ شده‌اند.
- `playwright.config.ts` و fixtureهای `tests/`: پروژهٔ آزمون راننده و آزمون‌های قبلی به دو API و دیتابیس موقت مستقل متصل‌اند. کاتالوگ سرویس‌ها و سهمیهٔ ورود امنیتی میان دو مجموعه مشترک نیست؛ هیچ محدودکنندهٔ سرور حذف یا ضعیف نشده است. هر دو سرور فقط روی loopback اجرا و پس از آزمون با کلید تصادفی پاک‌سازی می‌شوند.

## رفتارهای حساس حفظ‌شده

مدارک PNG، JPEG، WebP یا PDF، حداکثر ۳ MiB برای هر فایل‌اند؛ این محدودیت واقعی سرور است. امضای فایل نیز پیش از پیش‌نمایش بررسی می‌شود. هر سه مدرک فقط در ارسال نهایی همراه با ساختار اصلی `documents` به endpoint موجود ارسال می‌شوند. نام فایل و وضعیت خواندن، وارد قرارداد API نمی‌شوند. پیش‌نویس، رمز و تصاویر در حافظه‌اند و با refresh از ابتدا شروع می‌شوند؛ این رفتار در فرم توضیح داده شده است. حذف یا تعویض مدرک، ارسال فرم ایجاد نمی‌کند.

ثبت‌نام موفق صرفاً وضعیت بررسی را نشان می‌دهد و توکن حساب فعال نمی‌سازد. درخواست ردشده، علت و اطلاعات واقعی قبلی را از پاسخ ورود می‌گیرد و قابل اصلاح است. وضعیت بررسی در query مجوز نیست؛ refresh آن، ورود برای بررسی وضعیت واقعی را نمایش می‌دهد. نشست بازیابی‌شده پیش از نمایش عملیاتی از endpointهای محافظت‌شده بررسی می‌شود؛ رد دسترسی، نشست راننده را پاک می‌کند. خروج، دادهٔ راننده و پاسخ‌های دیررس او را از رابط کنار می‌گذارد.

QR و کد دستی از یک مسیر ثبت مشترک استفاده می‌کنند. کد چهاررقمی رشته می‌ماند و ارقام فارسی/عربی تبدیل می‌شوند. بازشدن صفحه، focus یا blur درخواست ثبت ایجاد نمی‌کند؛ تکمیل چهار رقم مطابق رفتار قبلی اقدام را آغاز می‌کند. دوربین فقط با اقدام صریح باز می‌شود و decoder فعلی در طول چند اسکن همان stream را حفظ می‌کند. بستن، تغییر تب و خروج، دوربین را آزاد می‌کنند.

خواندن QR به‌تنهایی موفقیت نیست؛ نتیجهٔ معتبر سرور مبناست. کد و QR به‌صورت HTML یا مقصد ناوبری اجرا نمی‌شوند. عملیات POST خودکار تکرار نمی‌شود. اگر پاسخ پس از ارسال قطع شود، نتیجه «نامشخص» است؛ کد مشابه در همان نشست خودکار دوباره ارسال نمی‌شود و اقدام «بررسی سوابق ثبت مسافر» فقط دادهٔ سرور را می‌خواند. تضمین نهایی ثبت اتمی و عدم کسر دوباره از کیف پول در سرور موجود باقی مانده است.

واحد `priceToman`، موجودی درآمد، قیمت سرویس و سابقهٔ ارسالی به رابط تومان است. تبدیل ریال/تومان در رابط دوباره انجام نمی‌شود. درآمد خالص و کمیسیون توسط سرور محاسبه می‌شوند. مقدار آغازین درخواست مسیر ۵۰٬۰۰۰ تومان، همان رفتار قبلی محصول است؛ حد ۱٬۰۰۰ تا ۵۰٬۰۰۰٬۰۰۰ از قرارداد فعلی آمده است. تازه‌سازی فرم را پاک نمی‌کند. ساعت سابقه با منطقهٔ `Asia/Tehran` نمایش داده می‌شود؛ اعتبار روز بلیت همچنان تصمیم سرور است.

## اجرا

با Node و وابستگی‌های فعلی پروژه:

```powershell
npm ci
npm --prefix backend ci
npm --prefix backend run dev
npm run dev -- --port 3002 --strictPort
```

تنظیم دیتابیس و API طبق راهنمای فعلی پروژه و فایل‌های نمونه است؛ فایل محیط واقعی و اطلاعات ورود در Git ثبت نمی‌شوند. آدرس محیط موجود: `http://127.0.0.1:3002/driver`. نام مستعار موجود `/deriver` حفظ شده است. تب‌های مستقیم `/driver?driverView=scan`، `/driver?driverView=request` و `/driver?driverView=profile` همان نشست واقعی را لازم دارند. ثبت‌نام عمومی `/driver?driverView=register` فرم خالی را باز می‌کند. production deploy یا ادغام با main انجام نشده است.

اجرای مرورگر شامل ۱۷ آزمون قبلی دانشجو/مدیریت/اسکن و ۹ آزمون راننده بود. هر ۱۸ حالت دانشجو و هر ۱۰ حالت راننده در پنج عرض بررسی شدند. در ۳۹۰ پیکسل، axe برای تمام حالت‌های مرجع اجرا شد و هیچ مسئلهٔ serious/critical در برچسب‌های WCAG 2 A/AA و 2.1 AA گزارش نشد. آزمون‌ها بارگذاری فونت و تصاویر، نبود overflow افقی، در دسترس‌بودن آخرین ردیف، جابه‌جایی تب، refresh، ورودی مستقیم و نام مستعار `/deriver` را نیز بررسی کردند.

شواهد محلی در `backend/tmp/driver-redesign/` قرار دارند: ۵۰ PNG از اجرای واقعی، `contact-390.jpg` و contactهای چهار عرض دیگر، گالری `index.html` و `manifest.json` شامل اندازه و هش تصاویر. بستهٔ قابل انتقال `backend/tmp/Vira_Driver_UI_Review.zip` همین شواهد و نسخهٔ این گزارش را دارد. این فایل‌های تولیدشده، خروجی build، لاگ‌ها و دیتابیس‌های تست در Git ثبت نشده‌اند. سورس، دارایی‌های مستقل، آزمون‌ها و همین گزارش فایل‌های تحویل مخزن هستند.

بازبینی امنیتی تغییرات و مرزهای مستقیم انجام شد: دادهٔ قانونی، نام، پیام خطا و دادهٔ QR به HTML اجرایی تبدیل نمی‌شوند؛ پیش‌نمایش مدارک فقط data URLهای محدود به MIMEهای قرارداد را می‌پذیرد؛ رمز و مدارک وارد storage یا لاگ محصول نمی‌شوند؛ query و cache مجوز نمی‌سازند؛ پاسخ قدیمی حساب خارج‌شده کنار گذاشته می‌شود؛ و POST ثبت مسافر یا مسیر خودکار تکرار نمی‌شود. کنترل مالکیت، وضعیت فعال، اعتبار روز سفر و ثبت اتمی سرور با آزمون API موجود نیز بررسی شدند. هیچ نقص مادیِ حل‌نشده‌ای ناشی از این تغییرات در بازبینی مشاهده نشد؛ این نتیجه، ادعای آزمون نفوذ کامل سامانه نیست.

## محدودیت‌های دقیق

- مرجع ZIP نهایی در محیط موجود نبود. اصلاح نسخهٔ 05 از متن صریح مأموریت اعمال شده است؛ تطبیق پیکسلی با PNG اصلاح‌شدهٔ تحویل‌نشده قابل ادعا نیست.
- امکان آزمون دوربین سخت‌افزاری، مرورگر Safari/Firefox یا صفحه‌کلید مجازی روی گوشی فیزیکی فراهم نبود. stream نرم‌افزاری، jsQR، رد مجوز، بستن پیش از آماده‌شدن دوربین و آزادشدن منابع در آزمون مرورگر بررسی می‌شوند؛ این جایگزین ادعای تست سخت‌افزار نیست.
- endpoint مستقلی برای بازیابی وضعیت درخواست بررسی‌شونده بدون ورود وجود ندارد؛ پس از refresh باید ورود انجام شود. رمز و مدارک برای بازسازی این حالت در storage نگهداری نمی‌شوند.
- endpoint رسید عملیات اسکن برای تطبیق خودکار پاسخ گم‌شده وجود ندارد؛ رابط نتیجه را قطعی اعلام نمی‌کند و فقط سوابق معتبر را برای بررسی در دسترس می‌گذارد.
- همهٔ عملیات آزمون در دیتابیس‌های موقت `vira_test_*` روی loopback انجام می‌شوند. پرداخت، ثبت مسافر یا تغییر دادهٔ عملیاتی برای آزمون انجام نشده است.
