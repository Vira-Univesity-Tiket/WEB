# اجرای محلی روی ویندوز

فرانت این محیط روی `http://127.0.0.1:3002` و بک‌اند روی `http://127.0.0.1:5005` اجرا می‌شوند.
پورت‌های ۳۰۰۰ و ۳۰۰۱ این سیستم در اختیار برنامه‌های دیگرند؛ فرانت با پورت صریح ۳۰۰۲ اجرا می‌شود.
درخواست‌های `/api1` از proxy محلی Vite به بک‌اند می‌رسند.

## پایگاه داده و تنظیمات

- MySQL 8.4 در کانتینر `vira-web-mysql-local` روی `127.0.0.1:33317` اجرا می‌شود؛ MySQL موجود سیستم تغییر نکرده است.
- داده‌های برنامه در دیتابیس `vira_local` و volume پایدار `vira-web-mysql-local-data` قرار دارند.
- `.env` شامل تنظیمات برنامه، رمزهای تصادفی مستقل، حساب مدیر و URL مخصوص آزمون محلی است.
- `.env.mysql` شامل تنظیمات راه‌اندازی کانتینر است. هر دو فایل از Git خارج‌اند و دسترسی آن‌ها به حساب جاری ویندوز محدود شده است.
- برنامه از کاربر محدود `vira_local` استفاده می‌کند؛ اتصال دارای مجوز ساخت/حذف دیتابیس فقط برای آزمون‌های محلی است.
- `BACKEND_NODE_ENV=development`، `BIND_HOST=127.0.0.1`، `TRUST_PROXY=false` و CORS مخصوص فرانت محلی تنظیم شده‌اند.
- دادهٔ کاتالوگ نجف‌آباد فقط در همین دیتابیس محلی وارد می‌شود؛ این داده برنامه یا تعرفهٔ رسمی دانشگاه نیست. جزئیات در [راهنمای کاتالوگ](NAJAFABAD-SERVICES.md) است.

نام کاربری مدیر مقدار `ADMIN_USERNAME` و رمز آن مقدار `ADMIN_PASSWORD` در `.env` است.
صفحهٔ ورود مدیریت در `/mohd/super/admin` قرار دارد. رمزها را در مخزن، پیام یا خروجی عمومی کپی نکنید.
رمز رانندگان واردشده فقط در فایل خصوصی `~/.vira-private/najafabad-*/driver-credentials.json` ذخیره می‌شود.
روی ویندوز دسترسی NTFS آن به حساب ایجادکننده محدود می‌شود؛ روی سیستم‌های POSIX مجوزهای پوشه و فایل `0700` و `0600` هستند.

## اجرای دوباره

ابتدا Docker Desktop را اجرا و کانتینر موجود را روشن کنید:

```powershell
docker start vira-web-mysql-local
```

سپس در یک ترمینال در ریشهٔ پروژه:

```powershell
npm --prefix backend start
```

و در ترمینال دوم در همان پوشه:

```powershell
npm run dev -- --host 127.0.0.1 --port 3002 --strictPort
```

بستن ترمینال‌ها یا `Ctrl+C` سرویس مربوط را متوقف می‌کند. برای توقف دیتابیس بدون حذف داده:

```powershell
docker stop vira-web-mysql-local
```

اگر کانتینر حذف شده ولی volume هنوز موجود است، می‌توان همان داده را با تنظیمات خصوصی موجود دوباره متصل کرد:

```powershell
docker run --detach --name vira-web-mysql-local --restart unless-stopped --publish 127.0.0.1:33317:3306 --env-file .env.mysql --mount type=volume,source=vira-web-mysql-local-data,target=/var/lib/mysql mysql:8.4
```

## اعتبارسنجی

```powershell
npm run typecheck
npm run lint
npm test
npm run build
node --env-file=.env --test tests/api.integration.test.mjs tests/catalog.integration.test.mjs
node --env-file=.env node_modules/@playwright/test/cli.js test
npm audit
npm --prefix backend audit
```

آزمون‌های API دیتابیس‌های تصادفی `vira_test_*` را ایجاد و حذف می‌کنند؛ دیتابیس برنامه هدف آزمون نیست.
برای آزمون pool تک‌اتصالی، پیش از دستور API مقدار `$env:VIRA_TEST_POOL_SIZE = '1'` را در همان ترمینال قرار دهید.
برای بررسی بیلد تولید، پس از build مقدار `$env:VIRA_BROWSER_PREVIEW = 'true'` را پیش از دستور مرورگر قرار دهید.
اجرای مرورگر به Chromium مربوط به Playwright نیاز دارد که با `npx playwright install chromium` نصب می‌شود.

## اصلاحات لازم برای راه‌اندازی

- `BIND_HOST` امکان محدودکردن listener بک‌اند به loopback را فراهم می‌کند؛ نبود این متغیر رفتار میزبان‌های فعلی را حفظ می‌کند.
- پوشه‌های جدید پشتیبانی از جداکنندهٔ امن `_` استفاده می‌کنند؛ فایل‌ها و مسیرهای قدیمی بازنویسی نمی‌شوند.
- خروجی رمزهای کاتالوگ پیش از نوشتن اطلاعات با مجوز واقعی سیستم‌عامل محافظت می‌شود. آزمون ویندوز ACL را بررسی می‌کند و آزمون POSIX همان modeها را کنترل می‌کند.
- پایان آزمون مرورگر منتظر پاک‌شدن دیتابیس و فایل‌های همان اجرا می‌ماند؛ پاک‌سازی به دریافت signal خروج در ویندوز وابسته نیست. مسیر خاموش‌کردن فقط در سرور آزمون loopback و با کلید تصادفی همان اجرا فعال است.
- lockfileهای ریشه و بک‌اند برای رفع هشدارهای وابستگی‌ها به‌روز شده‌اند. override نسخهٔ `minimatch` به `^11.0.1` زنجیرهٔ ابزار lint را به نسخهٔ اصلاح‌شده محدود می‌کند؛ lint، TypeScript و build باید همراه این تغییر بررسی شوند.

منابع اصلاح وابستگی‌ها: [body-parser](https://github.com/expressjs/body-parser/security/advisories/GHSA-27r3-jxmh-p828)،
[Vite](https://github.com/vitejs/vite/security/advisories/GHSA-8g5g-mxqh-grgj)،
[minimatch](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249).
تفاوت مجوز فایل در ویندوز در [مستند Node.js](https://nodejs.org/api/fs.html#fschmodpath-mode-callback) توضیح داده شده است.

## نتیجهٔ بررسی محلی — ۴ نوامبر ۲۰۲۶

محیط بررسی Node.js `24.18.0` و MySQL `8.4.11` بود.
۱۵ آزمون واحد، ۲۱ آزمون API و کاتالوگ با pool تک‌اتصالی و ۸ سناریوی مرورگر موفق بودند؛ مجموع ۴۴ سناریوی مستقل.
هر ۸ سناریوی مرورگر روی خروجی تولید نیز اجرا و موفق شدند.
TypeScript، lint، build، بررسی سازگاری هر دو lockfile و `git diff --check` موفق بودند.
`npm audit` کامل در ریشه و بک‌اند، هر دو صفر هشدار گزارش کردند.

بازبینی امنیتی تغییرات، مجوز NTFS فایل رمزها، مسیر ذخیرهٔ پشتیبانی، مالکیت ضمیمه، رد مدیریت بدون ورود،
محدودیت loopback، نبود مسیر خاموش‌کردن آزمون در برنامهٔ اصلی و حفاظت از فایل‌های محیط را پوشش داد.
درخواست مستقیم فایل‌های محیط از Vite با `403` رد شد و رمزهای تولیدشده در خروجی build پیدا نشدند.
پس از پایان آزمون مرورگر، هیچ دیتابیس آزمایشی باقی نماند.
وقفهٔ ارتباط ماشین مجازی Docker با راه‌اندازی مجدد موتور برطرف شد؛ ماندگاری ۲۱ ایستگاه، ۶۰ راننده و ۱۲۰ برنامه و سلامت بک‌اند دوباره بررسی شد.
گزارش‌های اجرایی موفق در مسیر محلی و خارج از Git، `backend/tmp/validation/`، نگهداری می‌شوند.

این محیط محلی است. درگاه پرداخت واقعی و انتشار روی cPanel به تنظیمات و دسترسی جداگانهٔ همان سرویس‌ها نیاز دارند؛ در این راه‌اندازی فعال نشده‌اند.
