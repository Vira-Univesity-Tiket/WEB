# بازطراحی رابط دانشجو و مسافر ویرا

## نگاشت مرجع به رابط فعلی

۱۸ JPEG شماره‌دار موجود در `Documents/virauser` بررسی شدند؛ همان شماره‌های PNGهای نام‌برده‌شده در درخواست، مبنای تطبیق‌اند. فایل ZIP برای دسترسی به این ۱۸ مرجع لازم نیست.

| مرجع  | محل فعلی                    | حالت و کامپوننت مقصد                                              |
| ----- | --------------------------- | ----------------------------------------------------------------- |
| 01    | آماده‌سازی برنامه           | `StudentSplash`، وابسته به آماده‌شدن تنظیمات و دریافت اولیهٔ حساب |
| 02–03 | فرم ورود در `/`             | `AuthView`، تب ورود و ثبت‌نام با اعتبارسنجی موجود                 |

فلش گردان در کد اولیه تازه‌سازی ایستگاه‌ها/سرویس‌ها را اجرا می‌کند، نه تعویض مسیر. واحد افزایش موجودی API تومان است؛ قیمت و موجودی نمایش داده‌شده نیز توسط قرارداد فعلی آماده می‌شوند و دوباره به ریال تبدیل نمی‌شوند. حد ضمیمهٔ پیش‌فرض سرور ۵ فایل، ۵ مگابایت برای هر فایل و ۸ مگابایت در مجموع هر پیام است. این تفاوت با نوشتهٔ تصویر باید در راهنمای فرم رعایت شود.

بک‌اند، schema و migration، قراردادهای API، توکن‌ها و محل نگهداری نشست، پنل رانندگان و پنل مدیریت در محدودهٔ ویرایش نیستند. شاخهٔ کار `feat/vira-ui-redesign` است؛ ادغام و انتشار عملیاتی انجام نمی‌شود.

- `components/student/StationPicker.tsx`: انتخاب مستقل مبدأ/مقصد، جست‌وجوی محلی در کل فهرست واقعی، مهار انتخاب ایستگاه مقابل، بستن بدون پاک‌شدن انتخاب، قفل پس‌زمینه، محدودکردن فوکوس و بازگرداندن آن. انتخابگر قدیمی راننده تغییر نکرده است.
- `components/student/AttachmentPicker.tsx` و `utils/studentAttachments.ts`: ورودی واقعی چندفایلی، حذف قبل از ارسال، محدودیت‌های فعلی سرور، توقف خواندن فایل هنگام خروج و حذف اطلاعات صرفاً نمایشی از payload.
- `components/student/TicketDocument.tsx` و `utils/downloadTicket.ts`: نمایش و دانلود بلیت واقعی، QR تولیدشده با کتابخانهٔ موجود، شناسهٔ اصلی و کد چهاررقمی مستقل، وضعیت اعتبار و امکان ثبت نظر طبق وضعیت سوارشدن. ارتفاع فایل دانلودی با طول نام مسیر هماهنگ می‌شود.
- `views/AuthView.tsx`, `HomeView.tsx`, `BusBookingView.tsx`, `TicketsView.tsx`, `WalletView.tsx`, `SupportView.tsx`, `FeedbackView.tsx`: پیاده‌سازی صفحه‌ها و حالت‌های مرجع با داده و عملیات موجود؛ جزئیات پشتیبانی، ادامهٔ گفتگو، TXT و ضمیمه، آرشیو و نظر سفر، ویرایش/حذف ایده و پاسخ مدیریت حفظ شده‌اند.
- `hooks/useSnappLogic.ts`, `App.tsx`, `utils/studentNavigation.ts`: اتصال پوسته به state موجود، تفکیک خطا از فهرست خالی، یکی‌کردن دریافت‌های همزمان، کنارگذاشتن پاسخ دیررس مسیر/نشست، حفظ محافظ خرید تکراری، و نگهداری صفحهٔ فعلی در query مجاز `view`. نام و بدنهٔ endpointها عوض نشده‌اند.
- `types.ts`, `utils/numberUtils.ts`, `index.tsx`, `components/QrCodeImage.tsx`: نوع وضعیت دریافت، قالب‌بندی نمایشی ارقام با حفظ صفر ابتدایی، بارگذاری CSS و یکدست‌کردن واژهٔ «بلیت» در متن جایگزین QR؛ مدل‌های تجاری تغییر نکرده‌اند.
- `services/apiService.ts`: اصلاح محدود تابع دانلود احرازشده؛ URL ساخته‌شده به آدرس همان مبدأ تبدیل می‌شود تا پیشوند API دوباره اضافه نشود. این خطای قدیمی، دانلود TXT و ضمیمه را به مسیر ناموجود `/api1/api1/...` می‌فرستاد. نام endpoint، header، payload، مجوز و سیستم دریافت داده تغییر نکرده‌اند.
- `tests/student-ui.test.ts` و `tests/browser/student-*.spec.ts`: پوشش ناوبری مجاز، ضمیمه، ارز، انتخاب ایستگاه و پاسخ دیررس، خطای شبکه، مهار خرید چندباره، وضعیت درگاه، QR واقعی، فرم‌ها و پنج عرض مرجع. فقط selectorهای بخش دانشجو در آزمون‌های قبلی به متن و نقش جدید کنترل‌ها تطبیق داده شده‌اند.

## دارایی‌ها و تفاوت‌های آگاهانه با تصاویر

لوگوی اصلی `public/logo/welcome.png` و فونت `public/fonts/Vazirmatn[wght].woff2` موجود استفاده شده‌اند. تصویر مستقل اتوبوس از مرجع ۰۴، کیف پول از ۰۹، بلیت از ۰۸، هدفون از ۱۱ و گفتگو از ۱۳ استخراج شده‌اند و در `public/illustrations/` قرار دارند. متن، فرم، دکمه، ناوبری و QR بخشی از این تصاویر نیستند. راهنمای مسیر و تزئینات مسیر SVG مستقل‌اند.

برای خوانایی متن کوچک روی سطح آبی روشن، خاکستری توضیحات از `#66788D` به نزدیک‌ترین مقدار آزموده‌شدهٔ `#5C6F84` تیره‌تر شده است. نشان انتخاب مسیر نیز کنتراست کافی دارد. کنترل‌های لمسی، نام طولانی دانشگاه و اسکرول داخلی بر تطبیق ارتفاع ثابت اسکرین‌شات اولویت دارند. اطلاعات کارت سوم و ردیف‌های بیش از هشت ایستگاه با اسکرول در دسترس‌اند.

زمان رسیدن فقط وقتی سرویس آن را برگرداند نمایش داده می‌شود. مدل بلیت ذخیره‌شده زمان رسیدن ندارد؛ هنگام بازکردن دوباره از فهرست، خانهٔ دوم خلاصهٔ QR صندلی واقعی را نشان می‌دهد. زمان فرضی برای پرکردن تصویر ساخته نشده است.

## اجرا و ورود مستقیم

با تنظیمات محلی موجود و MySQL آماده، از ریشهٔ پروژه در دو ترمینال اجرا کنید:

```powershell
npm --prefix backend start
npm run dev -- --host 127.0.0.1 --port 3002 --strictPort
```

صفحهٔ ورود: `http://127.0.0.1:3002/`. پس از ورود، مسیرهای قابل بازکردن مستقیم و refresh عبارت‌اند از `/?view=booking`, `/?view=tickets`, `/?view=wallet`, `/?view=support`, `/?view=ideas`, `/?view=profile`؛ خانه همان `/` است. ورود راننده همچنان `/driver` است. query فقط نمای مجاز را انتخاب می‌کند و مجوز دسترسی ایجاد نمی‌کند. پنجره‌ها و تب‌ها URL مستقل ندارند. بازگشت از درگاه با query فعلی پرداخت حفظ شده است.

شرح تنظیمات خصوصی و اجرای موجود در `docs/LOCAL-DEVELOPMENT.md` است؛ هیچ رمز یا فایل محیطی داخل این تحویل ثبت نمی‌شود.

## محدودیت‌های تأیید

- پرداخت عملیاتی و کسر پول واقعی انجام نشده است. پیکربندی درگاه محیط محلی آمادهٔ پرداخت واقعی نیست؛ خطای واقعی ۵۰۳ شروع درگاه، واحد تومان، حفظ مبلغ، رد لینک با طرح ناامن و بی‌اعتباری `topupStatus=success` بدون تأیید سرور آزموده می‌شوند. آزمون‌های API موجود تأیید درگاه را با سرویس آزمایشی جداگانه می‌سنجند؛ بازگشت از درگاه بانکی واقعی تأیید نشده است.
- رزرو، موجودی، ظرفیت، پشتیبانی و ایده در آزمون مرورگر به بک‌اند واقعی پروژه و دیتابیس موقت `vira_test_*` متصل‌اند. داده‌های تصویریِ نمونه فقط fixture آزمون هستند؛ دیتابیس برنامه/عملیاتی هدف این آزمون‌ها نیست و fixture در پایان پاک می‌شود.
- API موجود حدود ضمیمه و افزایش موجودی را منتشر نمی‌کند. رابط با پیش‌فرض‌های فعلی کد سرور و همین محیط هماهنگ است: ۵ فایل، هر فایل ۵ مگابایت و مجموع ۸ مگابایت؛ افزایش موجودی ۱۰٬۰۰۰ تا ۵۰٬۰۰۰٬۰۰۰ تومان. اگر استقرار دیگری این حدود را از متغیرهای محیطی عوض کند، انتشار تنظیمات معتبر در API کار جداگانهٔ بک‌اند است و در این مأموریت انجام نشده است.
- واکنش‌گرایی، فوکوس، مرورگر touch، refresh و تاریخچه در Chromium/Playwright بررسی می‌شوند. کیبورد نرم‌افزاری و بریدگی صفحه روی سخت‌افزار واقعی iOS/Android، Safari و Firefox آزموده نشده‌اند؛ CSS از `dvh`، safe area و اسکرول داخلی استفاده می‌کند.
- همهٔ ۱۸ JPEG ارائه‌شده در دسترس بودند؛ فایل ZIP جداگانه استفاده نشده است. نسبت تصاویر مستقلِ استخراج‌شده و طرح SVG راهنمای مسیر ممکن است اختلاف جزئی با رندر اصلی داشته باشد.

## بررسی امنیت و رگرسیون محدودهٔ تغییر

مرور نهایی روی کد فرانت و مرزهای مستقیم آن انجام شد: تغییرندادن endpoint/payload/نشست، محدودبودن `view` به نماهای دانشجو و رد کلیدهای prototype، پاک‌شدن دادهٔ نشست قبلی، کنارگذاشتن پاسخ دیررس، حفظ کلید idempotency و عدم retry خودکار خرید، تشخیص وضعیت پرداخت فقط از endpoint معتبر، رد scheme ناامن درگاه، نمایش متن و نام فایل با React بدون HTML خام، و کنترل ضمیمه پیش از خواندن/ارسال. هیچ API یا مجوز تازه‌ای صرفاً در فرانت اختراع نشده و اسرار به bundle اضافه نشده‌اند.

رگرسیون‌های رزرو تا اسکن راننده و ثبت نظر، ورود راننده و درخواست مسیر، پنل مدیریت، cache خراب، فوکوس/صفحه‌کلید، refresh/تاریخچه و خروج با پاسخ دیررس با آزمون‌های قبلی و جدید بررسی شدند. خطای کنتراست متن توضیحی و نشان مسیر که در بررسی اولیه دیده شد اصلاح و روی بیلد دوباره آزموده شد. آزمون تکمیلی، خطای قدیمی پیشوند دوبارهٔ آدرس دانلود را آشکار کرد و اصلاح در همان تابع فرانت انجام شد. فایل‌های بک‌اند، قراردادهای سرویس، packageها و lockfileها در این بازطراحی تغییری نکردند.

| `node --env-file=.env node_modules/@playwright/test/cli.js test` با `VIRA_BROWSER_PREVIEW=true` | ۱۶ آزمون موفق: ۸ رگرسیون قبلی، ۳ مسیر خطا و ۵ جریان کاملِ ۱۸ مرجع در پنج عرض |
| همان دستور با `test student-retained-features.spec.ts` و `VIRA_BROWSER_PREVIEW=true` | ۱ آزمون تکمیلی موفق روی بیلد اصلاح‌شدهٔ دانلود؛ گفتگو، تیکت بدون فایل، ضمیمهٔ پاسخ و دانلود، TXT، تیکت بسته و ویرایش/حذف ایده |
| Axe با `wcag2a`, `wcag2aa`, `wcag21aa` | در هر ۱۸ حالتِ عرض ۳۹۰ و مسیرهای قبلی، مورد serious/critical باقی نماند |
| `npm audit --omit=dev` و `npm --prefix backend audit --omit=dev` | هر دو بدون آسیب‌پذیری گزارش‌شده در وابستگی‌های اجرایی |
| `git diff --check` و بررسی فهرست فایل‌های stage | موفق؛ خروجی build، محیط، کلید، دیتابیس، گزارش تولیدی و screenshot در stage نیستند |
| اجرای محلی `/` و `/api1/healthz` روی پورت ۳۰۰۲ | هر دو پاسخ ۲۰۰ |

برای اجرای آزمون کامل روی build در PowerShell:

```powershell
npm run build
$env:VIRA_BROWSER_PREVIEW = 'true'
node --env-file=.env node_modules/@playwright/test/cli.js test
```

اکنون کل مجموعه ۱۷ آزمون مرورگر دارد؛ اجرای ۱۶تایی و اجرای تکمیلی بالا جداگانه انجام شدند. پس از اصلاح محدود دانلود، آزمون واحد مبدأ/پیشوند، typecheck، lint، build و آزمون واقعی TXT/ضمیمه دوباره موفق شدند. بازطراحی ظاهری با همان CSS و دارایی آزموده‌شده باقی ماند.
