# بستهٔ ایستگاه و سرویس دانشگاه آزاد نجف‌آباد

## محتوا

- فایل داده: `backend/data/najafabad-services.json`
- ۲۱ ایستگاه: دانشگاه و ۲۰ مبدا در اصفهان و شهرها و محدوده‌های اطراف.
- ۶۰ حساب سرویس با ظرفیت‌های ۲۳، ۳۲ و ۴۴ نفر؛ سه ناوگان برای هر مبدا.
- ۱۲۰ برنامهٔ فعال: سه رفت به دانشگاه و سه برگشت به همان مبدا، با ساعت و قیمت متفاوت.
- قیمت در فایل به تومان است؛ ابزار آن را برای دیتابیس به ریال تبدیل می‌کند.

این برنامه با اختیار داده‌شدهٔ کاربر تعریف شده است و برنامه یا تعرفهٔ رسمی اعلام‌شدهٔ دانشگاه نیست. نام‌های رانندگان، شناسه‌های `VIRA-NAJ-*` و حساب‌ها برای راه‌اندازی سرویس تعریف شده‌اند؛ اطلاعات شخصی، شماره تلفن یا پلاک واقعی اشخاص جعل نشده است. تیم بهره‌برداری می‌تواند پیش از ورود داده‌ها، نام و پلاک ناوگان خود را در بخش `drivers` و `services` تطبیق دهد. تغییر قیمت، ساعت و ظرفیت نیز در همین فایل انجام می‌شود.

مختصات با `coordinateRole: area-reference` مرجع محدوده‌اند؛ نقطهٔ دقیق درِ دانشگاه یا محل مجاز توقف اتوبوس را تضمین نمی‌کنند. برای ایستگاه دقیق، مختصات محل سوارشدن را تنظیم و نقش آن را `boarding-point` قرار دهید. دانشگاه در [نشانی رسمی نجف‌آباد، بلوار دانشگاه](https://iaun.iau.ir/fa) تعریف شده است. مرجع جغرافیایی هر محدوده در فیلد `source` آمده است: © [مشارکت‌کنندگان OpenStreetMap، مجوز ODbL](https://www.openstreetmap.org/copyright).

## اجرای تیم توسعه روی سرور

ابزار از اجرای عادی برنامه جداست؛ صرف deploy یا restart داده‌ای اضافه نمی‌کند. پس از انتشار نسخه و اجرای مهاجرت‌های معمول برنامه، از ریشهٔ پروژه اجرا کنید. اتصال از همان فایل‌های خصوصی `.env` یا `backend/.env` و متغیرهای `DB_*` خوانده می‌شود؛ رمز دیتابیس را در Git یا متن دستور ننویسید.

۱. بررسی فایل، بدون اتصال به دیتابیس:

```sh
npm run catalog:najafabad -- --file backend/data/najafabad-services.json --validate
```

۲. بررسی دیتابیس مقصد و نمایش تعداد داده‌های جدید یا موجود، بدون ثبت تغییر:

```sh
npm run catalog:najafabad -- --file backend/data/najafabad-services.json
```

۳. ثبت داده‌ها؛ `your_actual_database_name` را با نام واقعی دیتابیس همین سرور جایگزین کنید:

```sh
npm run catalog:najafabad -- --file backend/data/najafabad-services.json --apply --confirm-database your_actual_database_name
```

اگر فقط پوشهٔ بک‌اند روی سرور نصب می‌شود، زیرپوشه‌های `data`، `scripts` و `services` را نیز همراه آن منتشر کنید. دستورهای بالا در خود پوشهٔ بک‌اند هم موجودند؛ مسیر فایل را `data/najafabad-services.json` بدهید. نمونهٔ بررسی بدون اتصال در انتشار فقط بک‌اند:

```sh
npm run catalog:najafabad -- --file data/najafabad-services.json --validate
```

نام تأییدشده باید هم با تنظیم اتصال و هم با نام واقعی دیتابیسِ متصل‌شده برابر باشد. جدول‌های موجود باید InnoDB باشند. ابزار جدول یا schema جدید نمی‌سازد؛ تنظیمات مالی، حساب مسافران، موجودی کیف پول، بلیط‌ها و سرویس‌های قبلی را تغییر نمی‌دهد.

هر رانندهٔ جدید یک رمز تصادفی مستقل دارد. فقط hash آن در دیتابیس ثبت می‌شود. فایل تحویل رمزها با دسترسی `0600` داخل پوشهٔ خصوصی `0700` در `~/.vira-private/najafabad-*/driver-credentials.json` ساخته می‌شود؛ مسیر فایل در پایان چاپ می‌شود و خود رمزها در خروجی یا Git قرار نمی‌گیرند. فایل را از مسیر خصوصی به مسئول مجاز سرویس تحویل دهید؛ در web root یا مخزن عمومی کپی نکنید. اجرای دوباره رمز رانندهٔ موجود را عوض نمی‌کند.

## رفتار ورود داده‌ها و رزرو

- عملیات ثبت، transaction و قفل مشترک اختصاصی دارد؛ اجرای هم‌زمان همین ابزار دادهٔ تکراری نمی‌سازد.
- اگر راننده غیرفعال باشد، پلاک یا ظرفیت تطبیق نکند، ایستگاه هم‌نام مبهم باشد، قیمت سرویس موجود فرق کند یا راننده در همان ساعت مسیر دیگری داشته باشد، عملیات متوقف و تغییرات همان اجرا rollback می‌شود. اطلاعات قبلی بازنویسی نمی‌شوند.
- در تغییر ایستگاه موجود، اختلاف مختصات بیش از `0.001` درجه در هر محور نیازمند بررسی دستی است؛ ابزار مختصات موجود را عوض نمی‌کند. برای استفاده از ایستگاه ازقبل‌موجود، نام را با رکورد صحیح آن تطبیق دهید.
- رانندهٔ جدید به مبدا محلی خودش تخصیص داده می‌شود. ایستگاه دانشگاه به همهٔ رانندگان تخصیص عمومی داده نمی‌شود؛ رانندهٔ هر سرویس با مجوز مالک همان سرویس می‌تواند QR رفت و برگشت خودش را بخواند.
- سرویس‌ها در `schedules` تعریف می‌شوند. طبق معماری فعلی، رکورد اتوبوس روزانه در اولین رزرو ساخته و ظرفیت از راننده گرفته می‌شود؛ ابزار اتوبوس روزانه یا بلیط ازپیش‌فروخته‌شده نمی‌سازد.
- برای برگشت، کاربر در رزرو بلیط، مبدا را دانشگاه و مقصد را شهر خود انتخاب می‌کند. هر جهت بلیط، QR، ظرفیت و پرداخت مستقل دارد؛ خرید رفت، بلیط برگشت یا تخفیف خودکار ایجاد نمی‌کند.
- برنامهٔ فعلی سرویس‌ها ساعت روزانه دارد؛ روزهای هفته و تقویم تعطیلی در مدل فعلی تعریف نشده‌اند. زمان‌ها به ساعت محلی ایران‌اند.
- در صورت قطع اتصال دقیقاً هنگام commit، نتیجه را با اجرای بدون `--apply` بررسی کنید. فایل خصوصی رمزهایی که پیش از commit ذخیره شده حفظ می‌شود تا در چنین وضعیتی اطلاعات ورود از دست نرود.

## بررسی انجام‌شده — ۲۰ اکتبر ۲۰۲۶

- ۱۵ آزمون واحد، ۲۱ آزمون API و ورود داده با pool تک‌اتصالی و ۸ سناریوی مرورگر روی preview تولید موفق بودند؛ مجموع ۴۴ آزمون مستقل.
- در دیتابیس موقت، برای هر ۲۰ مبدا سه گزینه در هر جهت دریافت و یک بلیط رفت و یک بلیط برگشت خریداری شد؛ جمع ۴۰ بلیط با کنترل کسر صحیح موجودی. ورود رانندهٔ ایجادشده، اسکن هر دو جهت و رد اسکن تکراری نیز بررسی شد.
- اجرای دوباره، دو اجرای هم‌زمان با دو اتصال مستقل، تداخل برنامه، تغییر ظرفیت راننده، حساب غیرفعال، تأیید نام دیتابیس و خطای ذخیرهٔ خصوصی رمزها بررسی شدند؛ ثبت ناقص و تغییر بی‌اجازهٔ اطلاعات موجود مشاهده نشد.
- اجرای CLI، مجوز `0600` فایل و `0700` پوشهٔ رمزها، عدم چاپ رمز و حفظ رمزها در اجرای دوباره را روی محیط محلی بررسی کرد.
- TypeScript، lint و build موفق بودند. بازبینی امنیتی ورودی‌ها، queryهای پارامتری، نبود endpoint ورود دادهٔ عمومی، hash رمزها، تخصیص محدود ایستگاه و transaction انجام شد. وابستگی جدید اضافه نشده و `npm audit --omit=dev` ریشه و بک‌اند صفر هشدار داشتند؛ وضعیت هشدارهای توسعهٔ گزارش قبلی تغییر نکرده است.
- این بسته مستقیم روی دیتابیس اصلی اجرا نشده است؛ اجرای روی سرور به تیم توسعه سپرده شده است.
